# Команда и вычислительный план v2

Редакция 27.11.2026. Три постоянных ПК RTX4070Ti/3090/3060, один run целиком
на одном ПК. Код/архитектура — пользователь с ассистентом; исполнители не
изменяют исходники/метаданные и передают оригинальные артефакты архивом.

## Этапы

1. Одна source release v2 и runs-v2.json, прежний data protocol/cache.
2. Новый preflight каждой карты: шесть моделей и реальный pretrained B-16.
3. 24 LR-задачи по8/GPU, 10 эпох, seed142, четыре LR/конфигурацию.
4. Сбор всех24, шесть LR, единый final-план и freeze.
5. 18 final по6/GPU: все шесть методов одного seed на одной карте.
6. Отдельная test evaluation18 моделей, norms и статистика двух серий.

Первые пять этапов реализованы в study_*.py; test/evaluate/analysis ещё следующий
этап. Команды — [09-v2-runs.md](09-v2-runs.md). Прежние v1 результаты остаются пилотными.

## Назначения LR

| Метод | 1e-4 | 1e-3 | 1e-2 | 3e-2 |
| --- | --- | --- | --- | --- |
| LP | 4070Ti | 3090 | 3060 | 4070Ti |
| A-iso | 3060 | 4070Ti | 3090 | 3060 |
| M-iso = M-16 | 3090 | 3060 | 4070Ti | 3090 |
| B-iso | 4070Ti | 3090 | 3060 | 4070Ti |
| A-16 | 3060 | 4070Ti | 3090 | 3060 |
| B-16 | 3090 | 3060 | 4070Ti | 3090 |

Каждый метод присутствует на каждой GPU, по восемь tasks на GPU. Это равномерность
по количеству, не доказанное равенство длительности. Run ID/назначения проверяются
по плану; после старта они не редактируются вручную.

## Назначения final

4070Ti seed42: LP,A-iso,M-iso,B-iso,A-16,B-16.
3090 seed43: A-iso,M-iso,B-iso,A-16,B-16,LP.
3060 seed44: M-iso,B-iso,A-16,B-16,LP,A-iso.

Порядок предопределён и ротируется. M-iso используется в обеих таблицах анализа
как одна модель каждого seed. Парные сравнения внутри seed проходят на одном ПК;
seed и GPU между блоками связаны, это ограничение оценки вариативности.

## Бюджет

42×10×18180 = 7 635 600 train-предъявлений.
42×10×2020 = 848 400 val-предъявлений.
18×25250 = 454 500 test-предъявлений.

Двенадцать v1 LR-проб заняли суммарно около139 GPU-минут (2,32 GPU-часа),
по исполнителям около46/35/58 минут, без первоначальной подготовки. Перенос
этих скоростей на новые методы/длительность — только предварительная оценка:
B-16 имеет больший rank/число параметров и ещё требует реального GPU preflight.
Вместо старой экстраполяции по короткому T4 использовать actual v2 measurements.

Календарное время параллельных очередей — максимум длительности исполнителей,
не сумма GPU-часов. Setup/download/test/retries/доставка считаются отдельно.
Локальные cache/checkpoints/results — постоянный диск. Проверить реальный запас
диска под cache, последние checkpoints и best назначенных задач до серии.
