# Протокол эксперимента

Редакция 25.11.2026: проект до реализации. Подтверждено пользователем: пять дней, пять участников; весь код и архитектуру ведут пользователь с ассистентом. Сначала бесплатный Colab, затем RTX 4070 Ti, RTX 3090, RTX 3060. Платных вычислений нет. Пользователь согласовал основной план: 20 200 изображений, пять эпох, LR search, три seed A/M/B и LP. Начата реализация bootstrap/PEFT-сборки и synthetic smoke. Полный data/Trainer pipeline ещё не реализован; экспериментальное обучение не запускалось. Технические решения приняты и описаны в архитектуре: штатные PEFT + Trainer, единый пайплайн Colab/ПК. Runtime-проверка закрепляет совместимый полный стек и общий профиль, измеряет скорость; это не поиск числа эпох.

## Вопрос и модель

Сравниваем LoRA в Attention, MLP и обеих частях ViT при одинаковом количестве обучаемых параметров. Основная серия ограничена сравнением при равном бюджете параметров; равный ранг и кривые по рангам в согласованный план не входят. Вывод ограничен выбранной моделью, данными и коротким режимом обучения. Равные параметры не означают равные FLOPs/память/время; деление бюджета Both 50/50 — одна конкретная конфигурация.

Модель: `google/vit-base-patch16-224-in21k`, фиксированная revision. 12 блоков, hidden size 768, MLP 3072, 12 attention heads. RGB 224×224, patch 16×16: 196 patches + CLS. Новая линейная classifier head 768→101 по CLS-токену.

| Группа | Матрицы в каждом из всех 12 блоков | Linear input→output |
| --- | --- | --- |
| Attention | Q, K, V, O | четыре раза 768→768 |
| MLP | FC1, FC2 | 768→3072 и 3072→768 |
| Both | все шесть | как выше |

Frozen: исходные веса/bias backbone, LayerNorm, embeddings и CLS-токен. Trainable: LoRA A/B и новая head, включая её bias. LP обучает только head. «LoRA только в Attention» описывает место адаптеров: classifier тоже обучается.

LP checkpoint не переносим. Начальная head одинакова между методами одного seed: отдельная управляемая инициализация truncated normal mean=0, std=config.initializer_range, a=-2,b=2, bias=0 до PEFT и проверка хеша активной head после обёртки. Адаптеры создаёт штатный PEFT; обучение ведёт Transformers Trainer. LoRA использует стандартную инициализацию PEFT с B=0, поэтому начальное обновление backbone нулевое.

Целевая структура реализации — Transformers 4.57.1: `vit.encoder.layer.i.attention.attention.{query,key,value}`, `attention.output.dense`, `intermediate.dense`, `output.dense`. Полные имена Linear и формы проверяются перед запуском. Другую структуру не поддерживаем автоматически; полный version lock PEFT/torch/torchvision/Accelerate/Datasets/Python фиксируем после bootstrap до LR search. Публичные revisions модели/processor/dataset заменяем полными SHA в manifest.

## Данные

`ethz/food101`, фиксированная revision. Из официального train (75 750) один раз случайно выбираем **ровно 200 изображений каждого из 101 класса: 20 200 всего**. Внутри каждого класса случайно выделяем **180 train и 20 val**: итого **18 180 train / 2 020 val**, split seed 42. Сохраняем ID классов 0–100. Алгоритм фиксирован в [архитектуре](03-implementation.md): PCG64 seed42, сортированные классы/row indices, первые 200 после перестановки класса, из них 180/20. Сохраняем сам manifest с image byte hashes. Оставшиеся 55 550 изображений официального train не используем.

Обоснование: больше разнообразия внутри классов и менее шумный выбор LR/checkpoint, чем на 4 500/500, при меньшей стоимости, чем весь train. Это инженерный компромисс под пять дней, не доказанный минимум данных. Выборка 4 500/500 также допустима для PEFT, но больше не является нашим протоколом. Даже 20 200 примеров не гарантируют определённую accuracy или неизменность ранжирования методов на других объёмах данных.

Один manifest для всех машин: dataset revision, исходные row ID/индексы, labels, порядок, split seed, алгоритм стратификации и hashes. Проверяем отсутствие пересечений train/val. Повторно случайное разбиение в сессиях не создаём.

Официальный validation (25 250, по 250 на класс) — **итоговый test**. Он не участвует в выборе LR/эпохи/ранга/режима. Доступ к test loader разрешён только stage=final после protocol/freeze.json с выбранными LR всех четырёх методов и hashes очереди; затем по test настройки не меняем. Автоматически скачанные публичные test bytes в cache не считаются использованием test, но technical/lr_search не создают test loader и не вычисляют test метрики.

Train: RGB → RandomResizedCrop(224, scale=(0.08,1.0), ratio=(3/4,4/3), BILINEAR, antialias=True) → RandomHorizontalFlip(p=0.5) → ToTensor FP32 → Normalize по image processor. Val/test: RGB → Resize короткой стороны до 224, BILINEAR, antialias=True → CenterCrop(224) → ToTensor FP32 → Normalize. Версии torchvision/Pillow и mean/std сохраняем; повторной нормализации через processor нет.

### Исторический пример и 0,96

[Гайд PEFT](https://huggingface.co/docs/peft/main/task_guides/image_classification_lora) использует train[:5000] и сообщает val accuracy 0,96. В текущем [viewer Food-101](https://huggingface.co/datasets/ethz/food101) начальные записи одного класса: prefix нельзя считать случайной выборкой. Полный состав первых 5 000 пока не измерен.

Гайд остаётся методическим источником. **Воспроизведение 0,96 и отдельный Q/V-baseline REF исключены из согласованного плана.** Точный состав исторического запуска не установлен: нельзя утверждать, что высокая accuracy доказанно объясняется малым числом классов. Проверки исправности — модули, параметры, gradients, frozen weights, сохранение и загрузка. Наша accuracy на другом разбиении напрямую с 0,96 не сравнивается.

## Конфигурации

Head = 768×101+101 = 77 669. LoRA Linear добавляет r×(input+output).

`N_trainable = 77 669 + 12 × (6 144 × r_attn + 7 680 × r_mlp)`.

| ID    | Где LoRA   | r Attention / MLP | LoRA params | Всего с head |
| ----- | ---------- | ----------------- | ----------: | -----------: |
| LP    | нет        | 0 / 0             |           0 |       77 669 |
| A-iso | Q,K,V,O    | 20 / 0            |   1 474 560 |    1 552 229 |
| M-iso | FC1,FC2    | 0 / 16            |   1 474 560 |    1 552 229 |
| B-iso | обе группы | 10 / 8            |   1 474 560 |    1 552 229 |

B-iso получает по 737 280 LoRA-параметров на группу. Alpha каждой матрицы равна её r, включая mixed ranks: scaling=alpha/r=1. Это фиксирует множитель, но не гарантирует одинаковый эффективный шаг оптимизации при разных рангах.

## Настройки основной серии

| Параметр                  | Значение                                                          |
| ------------------------- | ----------------------------------------------------------------- |
| Эпохи                     | 5, без early stopping                                             |
| Effective batch           | 512 для полных accumulation-групп                                 |
| Microbatch / accumulation | исходно 16 / 32; подтвердить техническим запуском                  |
| Последняя группа          | 260 изображений, sample-weighted loss, не отбрасываем                               |
| Eval batch                | единый: первый помещающийся из 32,16,8 до LR search                                           |
| Precision                 | FP32 веса + AMP FP16 во всей серии                                |
| Optimizer                 | AdamW, betas=(0.9,0.999), eps=1e-8, weight decay=0                |
| Scheduler                 | linear decay до 0, warmup=0                                       |
| Loss / clipping           | cross entropy, smoothing=0, max grad norm=1                       |
| LoRA                      | dropout=0.1, bias=none; обычная LoRA без квантизации/rsLoRA/DoRA  |
| Head                      | совместно с LoRA, тот же LR; LP отдельно                          |
| Best checkpoint           | максимум val-2020 accuracy после эпохи; при равенстве ранняя эпоха |
| Логи / сохранение         | loss по шагам, val loss/accuracy и checkpoint каждую эпоху        |
| Final seeds               | 42,43,44                                                          |
| LR search seed            | 142, отдельно от final                                            |

**Пять эпох — согласованный общий бюджет**, первоначально взятый из гайда PEFT, а не установленный оптимум. При 18 180 train и effective batch 512 ожидаем около 36 optimizer updates за эпоху, **около 180 за run**. Фактический global_step и обработку неполной accumulation-группы проверяем технически. Все LR-пробы и final runs используют пять эпох и один scheduler; early stopping не применяется.

Validation измеряется после каждой эпохи, итоговый checkpoint выбирается из пяти. Ухудшение val при снижении train loss обсуждаем как возможное переобучение; продолжающийся рост к пятой эпохе — как ограничение бюджета. Это не повод автоматически продлевать отдельные runs. Изменение числа эпох означает новую версию протокола и повторение зависимых экспериментов, не входит в текущий план. Полные предварительные обучения трёх методов для подбора длительности не проводим.

Runtime profile общий, закрепляется до LR search. Фиксированный порядок выбора microbatch/accumulation: 16/32 → 8/64 → 4/128 по OOM на реально участвующей маленькой GPU; effective batch512. Если ни один не помещается, общий non-reentrant checkpointing для LoRA, проверка gradients и тот же порядок; при повторном OOM устройство исключается. Для LP тот же batch, checkpointing не нужен. Самовольное изменение профиля после старта серии запрещено.

Общий AMP FP16, FP32 веса/AdamW states, SDPA, TF32 выключен, float32 matmul precision highest, cudnn.benchmark=False, num_workers=0. Один run на процесс. Проверяем полную/неполную accumulation-группу и scheduler steps; applied/skipped AMP updates сохраняем. Десять consecutive skips останавливают run как technical_failed для диагностики, не как доказательство плохого LR. Нефинитные forward loss/logits/веса — numerical_invalid. Scheduler follows фактически применённые updates; отсутствие полной последовательности applied updates явно отражаем, не дорисовываем её.

Инициализация head/LoRA и sampler имеют отдельные RNG. Аугментации определены устойчивым seed от experiment seed/epoch/sample ID в изолированном RNG-контексте, не влияющем на model dropout. Один seed даёт одинаковые head, порядок данных и crops/flip между методами и LR-пробами. Между архитектурами не обещаем одинаковые dropout masks или побитовость разных GPU. Checkpoint после эпохи сохраняет resume state и более раннюю best_model при необходимости; перенос и повторная оценка — по правилам архитектуры.

## LR и объём

Для **LP, A-iso, M-iso и B-iso** одинаковая сетка начальных LR **{1e-4, 1e-3, 1e-2}**, поисковый seed 142 и пять эпох: **12 поисковых запусков**. Это грубый ограниченный поиск по двум порядкам величины, не гарантия глобального оптимума. Scheduler одинаково уменьшает начальный LR до нуля. В LoRA-методах выбранный LR общий для head и адаптеров; отдельный подбор двух LR не проводим.

Каждая проба начинается заново с исходного ViT и новой head/LoRA. Между LR-пробами одного метода совпадают исходные веса и случайности данных. Используем только основной manifest 18 180/2 020, а не технический поднабор. Test loader не создаём.

Для каждого LR выбираем checkpoint с максимальной val-2020 accuracy из пяти эпох, при равенстве раннюю эпоху. Затем для каждого метода выбираем LR с максимальной такой accuracy; при равенстве меньший LR. Сравниваем целые количества правильных ответов, чтобы избежать случайного tie-break из-за округления accuracy. Final начинается заново с seed 42,43,44, выбранный LR фиксирован для всех трёх. Поисковые пробы не переиспользуем как final.

| Стадия | Состав | Запусков | Test |
| --- | --- | ---: | --- |
| LR search | LP/A/M/B × 3 LR, seed 142 | 12 | нет |
| Final LoRA | A/M/B-iso × seeds 42,43,44 | 9 | по одному проходу для best checkpoint |
| Final LP | LP × seeds 42,43,44 | 3 | по одному проходу для best checkpoint |
| **Всего** | **12 LR + 12 final** | **24** | **12 итоговых оценок** |

### Границы поиска и неудачные пробы

- **Лучший LR на границе:** принимаем лучший проверенный; сетку автоматически не расширяем. Одинаковый ограниченный поиск для всех, без дополнительных шансов одному методу. В отчёте отмечаем границу и не называем LR оптимальным вообще.
- **Низкая accuracy при корректно завершённых пяти эпохах:** валидная проба. Не отбрасываем и не перезапускаем из-за плохого качества; не вводим порог accuracy для допуска.
- **Нефинитные loss/logits/веса:** остановка, статус numerical_invalid и причина. Не выбираем даже ранний хороший checkpoint такой пробы. Изолированный пропуск AMP step сам по себе не делает пробу невалидной; десять consecutive skips останавливают её как technical_failed для диагностики, без автоматического признания LR плохим.
- **Внешний сбой/OOM/ошибка кода:** статус interrupted или technical_failed, это не доказательство плохого LR. Продолжаем или повторяем ту же конфигурацию с тем же seed; попытки учитываем отдельно. Если меняется вычислительный профиль или содержательная реализация, проверяем совместимость результатов и при необходимости повторяем зависимую серию.
- **Есть хотя бы одна валидная проба метода:** выбираем лучшую среди валидных. Численно невалидные значения расходуют запланированные позиции поиска; новые LR взамен не добавляем. Состав и статусы всех трёх проб показываем в отчёте.
- **Все три численно невалидны:** LR метода не выбран; final для него не запускаем. Проверяем реализацию/вычисления. Если причина в диапазоне, пересмотр процедуры поиска оформляется новой версией протокола до итогового сравнения; произвольный запасной LR запрещён.

В final LR по seed не подбираем повторно. Низкую accuracy завершённого final не исключаем; численно разрушенный final не заменяем молча другим LR и не выдаём оставшиеся два seed за полный набор. Причину диагностируем и фиксируем, изменение протокола учитываем отдельно.

Технические проверки и повторные попытки сверх 24 запланированных конфигураций. REF, воспроизведение prefix-примера, равный ранг и rank sweep не входят в текущую очередь/бюджет. Будущие расширения требуют отдельного протокола; текущий test не используем для подбора их настроек.

## Метрики и основания

Главная: test top-1 accuracy, mean±sample std по трём seed. Также парные разницы в п.п., LoRA/head/trainable params, train/eval time отдельно, peak allocated/reserved VRAM train+val job и отдельного test, фактический размер adapter с head и dtype. LP сохраняет head. Стоимость только при одинаковых GPU/профилях; setup/sync отдельно. Анализ — [05-analysis.md](05-analysis.md).

Основания: [config модели](https://huggingface.co/google/vit-base-patch16-224-in21k/blob/main/config.json), [ViT 4.57.1](https://github.com/huggingface/transformers/blob/v4.57.1/src/transformers/models/vit/modeling_vit.py), [ViT main](https://github.com/huggingface/transformers/blob/main/src/transformers/models/vit/modeling_vit.py), [PEFT LoRA](https://huggingface.co/docs/peft/main/package_reference/lora).

Арифметика проверена; версии, модули в runtime, память, скорость, gradients и resume требуют технической проверки. Решения о данных, пяти эпохах и составе серии согласованы. Сценарный бюджет и его ограничения — в [04-team-and-plan.md](04-team-and-plan.md).
