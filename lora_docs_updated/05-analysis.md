Setup/download/retries и test отдельно. На границах CUDA synchronize. Peak allocated/reserved training job включает периодическую val, измеряется одним reset после подготовки модели, без вложенных reset Trainer; test — свежий процесс без optimizer, отдельный peak. Смешанный hardware resume исключаем из рейтинга стоимости, в accuracy учитываем с metadata и оговоркой. Если одинаковых условий нет, показываем реальные затраты с оборудованием без строгого рейтинга.

Predictions из best: model.eval()+inference_mode, детерминированные transforms, без shuffle, fixed ID/labels/order. В GPU не удерживаем все logits: сохраняем argmax и labels на CPU, NPZ с manifest hash/checksum. Повторный evaluate после сбоя не переобучает модель и не даёт нового seed. Test gate — freeze.json с LR всех четырёх методов и окончательной очередью; наличие публичных test bytes в cache не означает разрешение на оценку.

## Статистика

Главные описательные результаты: mean/std accuracy и средние парные A−M, A−B, M−B в п.п. Три seed ограничивают вывод об устойчивости обучения.

Для каждого seed и каждой пары: 2×2 таблица правильных/неправильных ответов, двухсторонний exact McNemar. **Девять тестов, Holm на все девять** как одну объявленную семью. Исходные три сравнения не учитывали повторы по seed. Не выбираем лучший seed и не считаем 3×25 250 ответов независимыми: изображения повторяются.

Парный bootstrap: 5 000 ресэмплов, seed 2026. Для каждой пары сначала усредняем по трём seed разность индикаторов правильности каждого изображения. Ресэмплируем изображения внутри каждого класса, по 250 с возвращением; общие индексы для методов/seed. Percentile 95% interval средней разницы — неопределённость по изображениям **условно на трёх обученных повторах**, не полноценный интервал будущих обучений. Три интервала описательные, без одновременного 95% покрытия.

McNemar относится к конкретной паре моделей. Вывод по эффекту/согласованности seed/ограничениям, не только p-value. Незначимость не доказывает равенства. Дополнительные seed планируем до test по ресурсу, не из-за неудобного p-value.

Основания: [McNemar](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html), [Holm](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html).

## Нормы

Best checkpoint, FP32, только реально адаптированные матрицы:

`ΔW = scaling × B @ A`, `R(W) = ||ΔW||_F / ||W_base||_F`.

Сохраняем layer/group/name/rank/scaling и квадраты норм. Для группы:

`R_group = sqrt(Σ ||ΔW||²_F / Σ ||W_base||²_F)`.

Classifier исключён, у LP норм нет. Это масштаб изменения, не причинная важность слоя. Проценты невзвешенно не усредняем. Heatmap строим для B-iso; seed 42 задаём заранее, значения остальных seed также сохраняем.

## Ограничение пяти эпох

Пять эпох — общий вычислительный бюджет, не доказанный оптимум. Показываем, на какой эпохе выбраны checkpoints. Если validation ухудшается при снижении train loss, отмечаем возможное переобучение; если растёт к пятой эпохе, не утверждаем полного схождения. Не продлеваем отдельные модели по результатам test. Вывод: качество методов на фиксированной выборке и при пяти эпохах после одинакового бюджета LR search; не максимально достижимое качество методов вообще. Предобучение делает малую выборку допустимой для PEFT; выбор 20 200 — компромисс разнообразия, точности validation и затрат, не утверждение о непригодности меньшего набора.
