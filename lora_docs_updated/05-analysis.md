# Анализ двух серий v2

Зафиксирован 27.11.2026 до test. Основная серия iso: A-iso/M-iso/B-iso.
Дополнительная rank16: A-16/M-iso/B-16. LP — общий описательный baseline.
M-16 = M-iso: одни predictions/history/weights на seed, не независимая реплика.
Шесть конфигураций × seeds42/43/44 =18 final-моделей.

## Приёмка

V1 и v2 не смешиваются. Проверить schema2/protocol/release/plan/freeze,
все24 LR-исхода и выбранные LR,18 trained/final, hashes/status/seed/дубли.
TRAINED не означает test evaluated: scientific test-таблица требует отдельной
успешной evaluation из подтверждённого best, predictions и её checksums.
Численно невалидные и технические попытки сохраняются в истории, не заменяются
другими LR/seed ради качества и не превращаются в вымышленные нулевые результаты.

Test25250 единый: совпадают sample IDs, true labels и порядок, не только длина.
Metrics хранят correct_count/sample_count и accuracy fraction без округления.
До test-прохода поля null. Все test настройки фиксируются до доступа к labels.

## Главный результат

Для каждой серии отдельная таблица: метод, ranks, trainable/LoRA/head params,
выбранный LR, test accuracy mean±sample std ddof1 по seed42/43/44, отдельные
значения и парные разницы в п.п. к LP и между тремя LoRA-методами серии.
Std не называется CI. Результаты rank16 интерпретируются с учётом разного бюджета
параметров; обе серии не изолируют универсальный причинный эффект места LoRA.

Сравнение Both-iso относится к50/50 budget split. Преимущество B-16 сопровождается
ростом параметров и не доказывает преимущество размещения независимо от бюджета.
Низкие валидные результаты не исключаются. Три seed, один backbone/manifest и
фиксированный лимит10 эпох ограничивают выводы; сходимость не предполагается.

## Подбор и динамика

Показать все24 LR-пробы, их статусы/причины, полные val-кривые, best epochs,
победу на границе сетки. Общий четырёхкандидатный поиск не гарантирует глобальный
оптимум. Старые12 v1 LR — отдельный пилот, без объединения с10-эпоховым поиском.

Кривые train loss/val loss/val accuracy/LR по optimizer updates и epochs для всех
seed либо заранее seed42. Best выбирается по val, test не участвует в выборе
эпохи. Ухудшение val при снижении train loss — возможное переобучение; рост на
10-й — ограничение бюджета, не разрешение продлить один метод.
Train loss из логов — по accumulation-группам в процессе обучения с меняющимися
весами и аугментациями, не post-epoch оценка фиксированной модели на всём train.
Best epoch ретроспективна; фактический training cost включает все10 эпох.

## Предопределённая статистика

В каждой серии пары A−M, A−B, M−B. Для каждой пары и каждого из трёх seed —
2×2 таблица индикаторов правильности и двухсторонний exact McNemar.
3 пары × 2 серии × 3 seed = **18 тестов**, одна общая коррекция **Holm на18**.
LP — описательные парные разницы, без дополнительных неучтённых p-values.
Не выбирать лучший seed и не объявлять 3×25250 ответов независимыми наблюдениями.
Общая M-iso создаёт зависимость сравнений; Holm не требует независимости тестов.

Парный bootstrap:5000 повторов, seed2026. Для каждой из шести пар серий сначала
усреднить по трём seed разность индикаторов правильности каждого изображения.
Ресэмплировать изображения внутри каждого класса (250 с возвращением), общие
индексы для методов/seed. Percentile95% интервал средней разницы условен на этих
трёх обученных повторах, не полноценный интервал будущих обучений.
Шесть интервалов описательные, без совместного95% покрытия.

Эффекты/устойчивость/ограничения важнее одного p-value. Незначимость не доказывает
эквивалентности. Новые seed/ранги не добавляются по неудобным test-результатам.

## Затраты и нормы

Фиксировать wall_train_job, val/save интервалы, train residual, setup/download,
export, test отдельно. CUDA synchronize на границах. Peak allocated/reserved
training job включает val; test — отдельный процесс без optimizer, собственные
peaks. MB=10^6 bytes, GiB=2^30 bytes. Export FP32: adapter+head либо LP head;
размер большого LP resume не сравнивается с компактным LoRA export.

Time/VRAM сравнивать внутри одинаковых GPU/profile/CPU/disk/cache. Иначе публиковать
фактические затраты с equipment без строгого рейтинга. Кривые по updates и время
отвечают на разные вопросы; равные параметры не означают равные FLOPs/time/VRAM.

Norms из best в FP32 по одной матрице: deltaW=scaling×B@A,
R=||deltaW||F/||W_base||F, classifier исключён. Групповые нормы:
sqrt(sum||deltaW||F² / sum||W_base||F²). Хранить layer/group/name/rank/scaling/
квадраты норм для всех seed. Не усреднять невзвешенные проценты. Нормы описывают
масштаб обновлений, не причинную важность слоя. Heatmap Both-iso и B-16 seed42
предопределены; значения остальных seed также сохраняются.
